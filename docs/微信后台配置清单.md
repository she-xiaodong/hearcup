## 0. 前置：确认小程序主体为企业类

`live-pusher` / `live-player`（实时音视频流组件）**不支持个人小程序**，只对企业类小程序开放，且仅限部分类目。

- 检查：微信公众平台 → 设置 → 基本设置 → 主体信息，确认「主体类型」为企业/组织。
- Hearcup 当前 AppID：`wxdae65eafc8e6174f`。
- 若仍是个人主体，需先完成主体变更/认证，否则下面的音视频权限无法开通。

## 一、开通「实时音视频流」组件权限（即你说的“音视频通话组件权限”）

> 澄清一个概念：微信小程序没有独立的「VoIP 通话权限」，语音/视频通话依赖的就是 `live-pusher`（推流）/ `live-player`（拉流）两个原生组件，对应后台的「实时播放/录制音视频流」权限。

**操作路径：**
1. 登录 [微信公众平台](https://mp.weixin.qq.com) → 左侧「开发」→「开发管理」→「接口设置」。
2. 找到 **「实时播放音视频流」** 与 **「实时录制音视频流」**，点击「开通」。
3. 若按钮灰置，说明当前类目不在开放范围内，需先在「设置 → 基本设置 → 服务类目」添加符合条件的类目（如「生活服务」「工具」「社交」等音视频相关类目）。

## 二、配置服务器域名白名单

**操作路径：** 微信公众平台 → 开发 → 开发管理 → 开发设置 → 「服务器域名」。

把下面四类域名全部加上（**request / socket / uploadFile / downloadFile**）。

### request 合法域名（https）
```
https://official.opensso.tencent-cloud.com
https://yun.tim.qq.com
https://cloud.tencent.com
https://webim.tim.qq.com
https://query.tencent-cloud.com
https://web.sdk.qcloud.com
https://ap-nanjing.cls.tencentcs.com
```
> 说明：前 6 个是 IM / TRTC 信令与票据所需；最后一个是腾讯云日志上报（可选，建议加上）。

### socket 合法域名（wss）
```
wss://wss.im.qcloud.com
wss://wss.tim.qq.com
wss://1600159614w4c.my-imcloud.com
```
> 说明：`wss://1600159614w4c.my-imcloud.com` 是 **IM 独立域名**（v3.4.6 起支持，格式为 `${SDKAppID}w4c.my-imcloud.com`），`1600159614` 是 Hearcup 的 SDKAppID，**务必加上**，否则收不到离线推送。

### uploadFile / downloadFile 合法域名
```
https://web.sdk.qcloud.com
https://cos.ap-shanghai.myqcloud.com
```
> 说明：若头像/证书上传走的是自己的后端或其它 COS 地域，请按实际存储域名追加。

### 注意
- 开发者工具可临时勾选「不校验合法域名」联调，但**真机必须配全**才能跑。
- 域名修改后，微信有 **5 分钟~数小时**的生效延迟，配完等一会儿再测。

## 三、申请订阅消息模板（离线触达兜底）

> 作用：倾听者被系统回收、收不到 IM 实时推送时，用「订阅消息」作为**最后一道兜底**，卡片可直达接听页。

**操作路径：** 微信公众平台 → 功能 → 订阅消息 → 「公共模板库」搜索选用。

**建议模板：**
- 类目：生活服务 / 工具
- 模板名称：**「通话邀请通知」**（或「服务提醒」「待办提醒」等通用模板）

**字段设计（申请时按模板关键词配置）：**

| 关键词 | 类型建议 | 内容示例 |
|---|---|---|
| 称呼 | thing | `小东`（发起人昵称） |
| 事项 | thing | `来电倾诉请求` |
| 时间 | time | `2026-08-30 17:36` |
| 备注 | thing | `点击进入接听` |

**跳转配置：** 模板「跳转类型」选小程序，落地页填接听页路径：
```
/pages/calling/calling?room_id={room_id}&caller={caller_nickname}
```

**⚠️ 关键避坑（老板重点强调）：**
1. **不要在小程序首次进入时就一次性申请订阅消息授权**，微信会拦截、且容易把用户授权率打崩。
2. 正确姿势：在「**开始倾听 / 上线接单**」这类关键动作时，才弹 `wx.requestSubscribeMessage` 让倾听者授权一次；授权一次 = 可发一条，下次再触发前再授权。
3. 订阅消息是「一次性订阅」，**每条通知都要用户授权过一次**；想长期稳定触达，主通道还是要靠 IM 离线推送（见下）。

## 四、隐私保护设置（麦克风 / 摄像头）

通话要采集麦克风（音频）和摄像头（视频），必须在小程序隐私保护里声明，否则真机会被系统拦截。

**操作路径：** 微信公众平台 → 设置 → 服务内容声明 → 用户隐私保护指引 → 「用户信息与隐私」。
- 勾选并填写用途：**「麦克风」**（用于语音通话）、**「摄像头」**（用于视频通话）。
- 更新后提交审核，审核通过才生效。

## 五、真机测试准备（必读）

1. **微信开发者工具不支持** `live-pusher` / `live-player` 原生组件，音视频必须在**真机**上验证。
2. 微信 App 最低版本：iOS / Android 均为 **8.0.40**；小程序基础库 ≥ **2.10.0**。
3. 通话音视频需要 **两台真机**（或真机 + 另一台设备）对测：A 发起呼叫，B 收到来电并接听。
4. 基础库版本：`project.config.json` 当前 `libVersion: "3.0.0"`，满足要求。

## 六、关键避坑要点汇总

| # | 要点 | 说明 |
|---|---|---|
| 1 | 订阅消息授权时机 | 首次进入**不**批量申请，在「开始倾听」等关键操作时再弹 |
| 2 | 拒绝授权后不重复弹 | 用户拒绝 VoIP/订阅消息后再次调用**不弹窗**，需引导其手动进「设置 → 语音视频通话提醒 / 订阅消息」开启 |
| 3 | Android 10 以下无锁屏弹窗 | 系统层面不支持锁屏来电弹窗，仅能微信通知提醒，已在小程序端做低版本适配提示 |
| 4 | ~~设备 VoIP 授权~~（已纠偏） | `wx.requestDeviceVoIP` 是「音视频通话 for 硬件设备」专用（需设备序列号/票据/型号），Hearcup 是纯软件无硬件，**此路不通**，不适用 |
| 5 | 小程序无系统级全屏来电 | 小程序运行在微信沙箱，无原生 CallKit 全屏来电；最强触达 = **IM 离线推送（微信服务通知）** + 点击直达接听页 |
